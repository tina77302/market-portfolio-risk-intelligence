현재 확인된 문제 위치는 수집 명령 실행 전, 예약 이벤트 생성·전달 단계입니다. GitHub 내부의 정확한 원인은 공개 로그만으로 확정하지 못했습니다. - 관련 테스트 43개와 YAML·내장 Python 문법 점검을 통과했습니다. 봉인한 모델·정책·발행 기록은 바꾸지 않았습니다.

수집과 감시가 같은 GitHub 예약 시스템에 의존하므로 둘 다 멈추는 경우를 외부에서 보장하지 않습니다. 독립적인 복구가 필요하면 외부 스케줄러의 실행 환경과 GitHub Actions 쓰기 인증을 별도로 준비해야 합니다.

## 외부 실행으로 전환할 때 필요한 구체적인 설정

- 실행 시각: UTC 월~금 23:37, 한국 시간 화~토 08:37.
- 요청: `POST https://api.github.com/repos/tina77302/market-portfolio-risk-intelligence/actions/workflows/portfolio-forward-validation.yml/dispatches`.
- JSON 본문: `{"ref":"main"}`.
- 인증: 대상 저장소에 한정한 Actions 쓰기 인증을 외부 실행 환경의 비밀 저장소에 설정합니다. 채팅이나 공개 파일에 토큰을 넣지 않습니다. 연결 앱의 인증을 추출해 재사용하지 않습니다.

저장소의 `render.yaml`은 웹 배포 준비 설정이며 외부 스케줄러가 배포된 증거가 아닙니다. 실제 사용 가능한 서버·스케줄러와 인증 연결은 아직 확인되지 않아 외부 자동화는 배포하지 않았습니다.
