## 구현한 동작

- 정책·코드·런타임·패키지·자산·비중과 범위 규칙을 봉인합니다.
- 새 구간 전에 당시 입력 버전, 베타, 실제로 완료된 과거 오차와 범위 오프셋을 저장합니다.
- 뉴욕 발행일보다 뒤에 나타난 첫 SPY 관측을 시작으로 고정하고, 이후 10개 관측이 생길 때까지 기다립니다. 달력상 임의의 평일로 값을 채우지 않습니다.
- 실제 주식·금리 충격은 구간 종료 후에만 입력합니다. 저장한 베타로 조건부 손실을 계산하며, 발행 파일을 다시 학습하거나 교체하지 않습니다.
- 평가 입력의 양끝 수정종가를 같은 버전에서 사용하고, 처음 관측한 시작 가격과의 개정 차이도 남깁니다.
- 결과·입력 receipt는 신규 생성만 허용합니다. 재실행 중복·해시 불일치·정책/환경 변경은 탐지합니다.
- 원래 145개 구간의 오차는 `retrospective_seed`로, 이후 평가 결과는 `forward:` 출처로 구분합니다. 누적 성과에는 실제 새 구간의 완료 결과만 합산합니다.

## 자동화와 보관

[워크플로](../../../.github/workflows/portfolio-forward-validation.yml)는 UTC 평일 23:37, 한국 시간 다음 날 08:37 실행 설정입니다. 실제 원격 실행을 검증한 것은 아닙니다.
동일 워크플로의 기존 artifact를 복원해 원래 Python·패키지 버전으로 이어 실행하고, 전체 보관소를 다시 보존합니다.
기록이 있던 실행에서 보관소 복원이 불가능하면 조용히 새 성과로 초기화하지 않습니다.
GitHub 예약은 지연될 수 있으며 보관 기간은 90일입니다. [예약 실행](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule), [artifact 보관](https://github.com/actions/upload-artifact)

## 확인한 범위

관련 분석·파이프라인 테스트 96개가 통과했습니다. 신규 10개 테스트는 가상 시장 자료와 임시 보관소를 사용하며 아래를 확인합니다.

1. 오래된 입력·수집 실패가 새 점수나 평가를 만들지 않음.
2. 시작 전 베타와 보정 자료가 저장되고 종료까지 대기함.
3. 10개 추가 관측 후 저장한 베타로 평가하고 재실행해도 결과를 중복·교체하지 않음.
4. 같은 평가 버전의 양끝 가격으로 실제 수익률을 계산하고 개정 차이를 추적함.
5. 변조·덮어쓰기·시계 역행·패키지 잠금 유실·정책 변경을 탐지함.
6. 뉴욕 당일 가격을 완료된 관측으로 오인하지 않음.
7. 평가 금리가 부족하면 대기하고 이후 확보 시 평가함.
8. artifact 경로 탈출을 거부하고 다른 호스트로 이동할 때 인증 헤더를 제거함.

모의 결과를 실제 새 기간의 포함률·정확도로 합산하지 않습니다. GitHub API 복원·업로드·원격 실행과 최신 실데이터 수집 성공은 확인되지 않았습니다.
기존 포트폴리오 시연도 `--check`로 재현됩니다.
